# 做视觉规范 + 做组件

把产品 UI **参考原稿**做成规范目录里的 **可切换组件**（能切的做变体，能绑的绑变量）。  
业务文案、文件、色板会换；拆法不变。理赔步骤条只是对照例，见 [references/worked-stepper.md](references/worked-stepper.md)。

| 会换 | 不换 |
|---|---|
| 文件、画布、token、文案、溯源节点 | 先锁矩阵、状态与内容分离、AL 结构 + Absolute 装饰、原稿对照 |

Token / 画布跟**当前产品**的设计系统走。本仓库默认 `alipay-app-design-system`（750 @2x）。别的产品不要抄支付宝蓝。API：`figma-use` + `figma-generate-library`。陷阱：[references/plugin-api-traps.md](references/plugin-api-traps.md)。规范页骨架：[references/spec-catalog.md](references/spec-catalog.md)。

---

## When to use

- 做 / 改视觉规范页、组件库目录、选择器、表单、步骤条、导航、列表、弹层
- 从参考原稿（Figma / Sketch 导入）还原成 Auto Layout 组件
- 加 `状态` 变体、TEXT 属性、Figma 变量
- 用户说和原稿不一样、切不了状态、点到的不是组件

不要用本 skill 去：手绘一张没有原稿的运营海报、写代码实现、做质感插画（那是 `c-end-visual-craft`）。

---

## Instructions

动手前先写这五行，用户没反对再画：

1. **文件与页**：用户 URL / 当前规范页（不要写死 fileKey）
2. **画布与 token**：该产品设计系统。Figma 保持设计稿原值；÷2 只给代码逻辑宽
3. **目录骨架**：抄**本文件已有规范页**的 Header / Section / 卡，不要另发明网格
4. **先搜再画**：本地组件 → 已订阅库 → 再新建。有库的按钮 / 导航 / 开关禁止手绘
5. **变体矩阵**（能切就做变体，能绑就绑变量）：

| 组件名 | 变体轴 | TEXT / BOOLEAN / 变量 | 溯源 node | 为何不烤死 |
|---|---|---|---|---|
| `域/中文 English` | `状态=` … | 标题、序号… | `123:456` | 原稿里能看见的切换 |

然后按 **原子 → 项 → 条 → 目录卡 → 文档** 做，每步截图对照原稿。写操作必须串行 `use_figma`，禁止编造 node id。

## 1. 铁律

1. **原稿图层是视觉真源。** Plugin API 量 x/y/w/h/fill/stroke/font/effect，再截图对照。禁止用截图模型估 px。
2. **两份原稿先当两份。** 看起来像「同一条 + 一个气泡」时分别 dump。布局差用变体，不要收成更干净的一种。
3. **状态只换皮，不换料。** 位置/选中/空态是 `状态`；标题、序号、标签是 TEXT。切「当前 → 未到」，该步文案和数字还在。
4. **点得着才能切。** 必须是 COMPONENT / INSTANCE（菱形）。套 Frame（点槽、卡壳）右栏没有变体。
5. **步骤条全家自适应。** 点、标、项、条、列表都要随容器和文案重排，不是只改最外层的条。项 **HUG** 标题；列表项 **FILL**；条用 **[项][间距 FILL + 连线/三角][项]**。拉宽实例必须铺开。点/圆直径固定。细则：[references/adaptive-stepper.md](references/adaptive-stepper.md)。
6. **结构 Auto Layout，装饰 Absolute。** 等分 FILL，拉开 SPACE_BETWEEN。底渐变 `STRETCH`。徽章/气泡 `MIN/MIN`。连线放进 FILL 间距并在项上 stub 接到圆边，禁止负 x 探进上一列（会盖住内圆，像穿过圆心）。禁止 Absolute + `MIN/MIN` 把列钉死。
7. **`resize()` 会缩放子层。** 小图居中在大热区：外框 `resizeWithoutConstraints`，内图形自己 resize 再设 x/y。
8. **还原产品能看见的；丢掉导入垃圾。** 半截进度线、错位徽章是稿。穿出透明边的叠线按可见边缘重画，不要整组 clone。
9. **用户指着原稿说「有」，就加回去。** 不要说「我帮你整理了」。吃不准：默认还原 + 再做一条变体。
10. **一屏对照再宣布完成。** 差 2px 的对齐、半截线、气泡坐标，以原稿为准。
11. **一次脚本只做一件可验证的事。** 失败=整段没执行。颜色 0–1。每调用最多一次 `setCurrentPageAsync`。禁止 `figma.notify` / `console.log`。
12. **先搜再画，禁止 detach。** 对齐问题用 AL / 约束 / 嵌实例解决，不要打散库组件。
13. **不删参考原稿。** 规范页末尾保留溯源分区；只 clone，不改原节点位置和内容。
14. **条上步数用变体切，整条能力用第二轴，不要再摊元件。** 当前步 = `状态=步骤1/2/3`；「有时整条有气泡、有时没有」= `查看修改=有/无`。`有` 时每个**已完成**步都出气泡（走到步骤3，步骤2 也要有）。不要为线/气泡新建 COMPONENT，不要让人从实例里删步。细则：[references/stepper-bar-lessons.md](references/stepper-bar-lessons.md)。

## 2. 做规范页（目录，不是产品屏）

规范页是给设计师扫组件的，不是一张业务稿。

1. **分区**：封面或标题 →（可选）色/字/间距标本 → 组件 Section → **参考原稿**。一个家族一个 Section。
2. **抄已有页**：Header、Section 宽、间距、卡片 pad 与文件里第一份已完成规范页对齐（本仓库选择器：Section 宽 2984、间距 80、Header 64）。没有先例就量用户指定的那页，不要发明新网格。
3. **组件还是产品宽**：目录可以很宽，**组件本身保持产品画布**（本仓库默认 750）。不要把组件拉成 2984。
4. **卡是壳，组件是芯**：卡背景、标题、状态标签不属于组件。组件透明或用产品底色，不要把目录灰底烤进组件。
5. **状态标签 = 变体值**：标签写「空态 / 回填」，变体就必须叫 `空态` / `回填`，格宽 = 变体宽，gap / 左 pad 与组件集一致。两轴时组件集 `WRAP` 成网格，标签分行写清第二轴。
6. **全家福 vs 可切实例**：组件集放目录展示。若 TEXT 默认值让所有主组件显示同一个「3」，把集藏起来，卡上放 **预览实例** `setProperties`。切状态请点实例，不要点外框。
7. **组件 description**：写「右栏切什么、TEXT 改什么、溯源 node id」。图层名可读：`域/中文 English`，禁止 `编组-2备份`、`Rectangle 123`。
8. **文档**：`docs/specs` 或该仓库约定路径，写清能切 / 不会跟着变 / 溯源 / 两态肉眼差。没量过的 px 标待确认，禁止写成 Exact。

## 3. 变体 / 属性 / 变量

### 3.1 变体

默认轴名 **`状态`**。Size / Type / 平台等独立维度用**第二轴**，不要揉进 `状态`。

步骤条（用户说「步骤123」「有时有查看修改」时）：

- `状态` = 当前走到哪一步（步骤1/2/3），**不是** `步骤2` / `步骤2-可修改`
- 第二轴 = 整条能力（`查看修改` 有/无），不是每一步一个元件
- `有` → 只给已完成步出气泡；步骤1 没有已完成步所以没有；步骤 n 则 1…n−1 都有

| 有稿就做 | 做成 |
|---|---|
| 选中、空态/回填、禁用、当前/已完成/未到 | `状态` |
| 会改高度/整列下移的装饰 | `状态`，不要只用 BOOLEAN 硬藏 |
| 互相独立的第二视觉 | 第二轴；默认=原稿；目录放不下就隐藏非默认变体 |

- **不要发明原稿没有的态。** 移动端 750 稿默认不做 hover/press，除非原稿有。
- 空 / 错 / 加载 / 禁用：有稿才做。
- 变体组合（轴相乘）**> 30** 就拆子组件。图标用 **INSTANCE_SWAP**，不要每个图标一个变体。
- 默认变体 = 原稿主态（最常见的那张），不是最空的那张，除非用户指定。

### 3.2 属性

| 用 | 不要 |
|---|---|
| TEXT：标题、序号、按钮文案 | 每个状态下写死不同数字/文案 |
| BOOLEAN：箭头、项上左右连线显隐（不改变高度） | 显隐会撑开高度时仍用 BOOLEAN（改用变体） |
| 暴露子实例 | 组合条里每一项还是 Frame |

TEXT 绑在**主组件图层**，不能绑实例子层。一套 TEXT 一个 `defaultValue`。目录数字用实例 `setProperties`。  
`isExposedInstance` 必须在实例进入父组件之后再设。

### 3.3 变量

能对上该产品语义 token 的 fill / 字号 / 间距 / 圆角就绑，并设 **scopes**（禁止 `ALL_SCOPES`）。  
对不上的一次性色按原稿写死并记进 spec，不要假装 Brand、不要第二套主色。  
间距优先 4/8 刻度；原稿量死的非刻度（如 129.5）以原稿为准，不要「取整成 128」。

## 4. 搭建顺序

1. **原子**（点、芯片、勾）：只要视觉态。数字随父级变 → 内层数字透明，父级 Absolute TEXT 绑 `序号`。
2. **项**（原子 + 标题）：嵌原子实例；切 `状态` 只换皮。
3. **条 / 面板**：AL 排项；间距 FILL，连线进间距 + 项上 stub 接到圆边（禁止负 x overflow）。底渐变 Absolute `STRETCH`。徽章/气泡 Absolute `MIN/MIN`。步数锁在变体里。
4. **溢出**：徽章/气泡可能探出 —— 父级不要随便开 clip；只在需要遮罩的图片/圆里 clip。
5. **热区**：不够点就加大透明槽，不要缩放图形。
6. **目录卡** + **description** + **文档**。
7. **Groups 先改 Frame + AL** 再做成组件。不要把 Group 直接当组件。

命名：`域/中文 EnglishName`；变体优先单轴 `状态=步骤1`。多轴写成 `状态=步骤2, 查看修改=有`。

## 5. 换场景

| 场景 | 怎么套 |
|---|---|
| 同一规范页下一刀 | 同一骨架；新溯源；能复用的原子直接嵌 |
| 同一设计体系、另一业务 | 同一 token/画布/库；换文案、字段、溯源 |
| 另一文件 / 另一产品 | 换 fileKey、画布、设计系统；**拆法照旧** |
| 不是步骤条 | 凡原稿有空/选中/禁用，就做 `状态` |

不要假设和已做组件同构。两份「步骤条」也可能列宽、y、装饰坐标全不同。

## 6. 验收

- [ ] 点实例，右栏能切锁过的每一轴；改 TEXT 预览不打乱布局
- [ ] 切 `状态` 后标题/序号还在
- [ ] 组合里的项是暴露实例，不是 Frame；没有 detach
- [ ] 组件截图 vs 溯源：线、尺寸、装饰坐标、字重、描边 cap/align 一致
- [ ] 透明热区无穿模残段；气泡/徽章没被 clip 裁掉
- [ ] 状态标签与变体值一致；组件未吃进目录卡背景
- [ ] 参考原稿还在，未被改动
- [ ] description 和 spec 写了切法与溯源
- [ ] 没有把 A 产品的 token/文案抄进 B 产品
- [ ] 步骤条点/标/项/条/列表均为自适应：项 HUG 或列表 FILL，条间距 FILL；拉到 900 四步铺满、连线跟着走、圆不变形
- [ ] 步骤条：右栏能切当前步；若有「整条有/无气泡」，第二轴在；走到最后一步时前面每个已完成步都有气泡
- [ ] 连线接到圆边，不穿过勾/数字；没有单独的线 COMPONENT；变体里步数固定

---

## 7. 禁止

- 把本 skill 理解成只做理赔步骤条
- Frame 冒充分状态组件；为对齐 detach 库组件
- 把两份原稿收成一种更干净的设计
- 用 `resize` 放大带装饰的组
- 在实例子层绑 TEXT；为目录发明原稿没有的态
- 整组 clone 导入叠线；没并排截过原稿就宣布完成
- 删改参考原稿；把规范卡背景烤进组件
- 手绘已有库的按钮 / 导航 / 开关
- 移动端稿无端加 hover
- 把量死的 129.5「取整」掉
- 步骤条只改条、不改项；用 FIXED spacer/列宽把内容钉在左边
- 把步骤圆 `resize` 拉扁来「铺满」
- 为连线/气泡再摊一批原子；用删实例子层来「少一步」
- 把「步骤1/2/3」收成「步骤2 / 可修改」；`查看修改=有` 时漏掉后面已完成步的气泡
- 连线负 x 探进上一列，画在内圆上面

## Examples

- 「把选择器做成规范组件」→ 锁 选中/未选；选项原子复用进选项组和表单行。
- 「步骤条和原稿不一样」→ 并排截图 + dump 连线每条 x/w；还原看得见的半截线，重画穿模叠线。
- 「步骤123 / 查看修改有时有有时没有」→ 条上两轴；已完成步才出气泡；不要再做线元件。见 [stepper-bar-lessons.md](references/stepper-bar-lessons.md)。
- 「点了切不了状态」→ 查是否点到 Frame；改成项实例并暴露；状态与序号拆开。
- 「给理财做一套表单行规范」→ 同一拆法，换 token/文案/溯源，不要带理赔字段。
