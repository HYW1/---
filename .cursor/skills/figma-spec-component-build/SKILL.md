# 做规范 + 做组件（不绑业务）

把产品 UI **参考原稿**做成规范目录里的 **可切换组件**。  
业务文案、文件、色板都会换；拆法不变。

| 会换的 | 不换的 |
|---|---|
| 文件、画布、token、中文案、溯源节点 | 先锁矩阵、状态与内容分离、AL 结构 + Absolute 装饰、原稿对照 |

**理赔不是范围。** 同一套流程可用于信用卡、理财、到店、后台、另一个小程序——只要有原稿和规范页。理赔步骤条只作为对照例：[references/worked-stepper.md](references/worked-stepper.md)。

配套：API 用 `figma-use` + `figma-generate-library`。本仓库默认 token 走 `alipay-app-design-system`；**别的产品用那套产品的设计系统 skill / 库**，不要把支付宝蓝硬套过去。乱码/错图层才走 `claims-visual-guard`（仅量那批工具稿时）。

---

## 0. 每次先定场景，再锁矩阵

动手前写清这四行（用户没反对再画）：

1. **文件与页**：用户给的 Figma URL / 当前规范页（不要写死某一个 fileKey）
2. **画布与 token**：该产品的设计系统（本仓库默认 750 @2x + APP token）。Figma 里保持设计稿原值，÷2 只给代码逻辑宽。
3. **目录骨架**：抄**本文件已有规范页**的 Header / Section / 卡片，不要另发明一套网格。
4. **变体矩阵**：

| 组件名 | 变体轴 | TEXT / BOOLEAN / 变量 | 溯源 node | 为何是变体不是烤死 |
|---|---|---|---|---|
| `域/中文 English` | `状态=` … | 标题、序号、显示箭头… | `123:456` | 原稿里能看见的切换 |

**能做成变体的，就做成变体 + 能绑的就绑变量。** 不要只摆静态全家福。设计师要在右栏切，点的必须是 **实例（菱形）**。

## 1. 铁律

1. **原稿图层是视觉真源。** Plugin API 量 x/y/w/h/fill/stroke/font，再截图对照。禁止用截图模型估 px。
2. **两份原稿先当两份。** 看起来像「同一条 + 一个气泡」时，分别 dump。布局差（整列下移、装饰坐标）用变体，不要收成一种更干净的设计。
3. **状态只换皮，不换料。** 流程位置、选中、空态是 `状态`；标题、序号、标签是 TEXT。切「当前 → 未到」时，该步骤的文案和数字还在。
4. **点得着才能切。** 可切对象必须是 COMPONENT / INSTANCE。套一层 Frame（点槽、卡片壳）右栏没有变体。
5. **结构 Auto Layout，装饰 Absolute。** 等分 FILL，拉开 SPACE_BETWEEN，原稿空隙用 spacer 量死。光晕、连线、徽章、气泡 Absolute，且压在内容下面。
6. **`resize()` 会缩放子层。** 小图居中在大热区：外框 `resizeWithoutConstraints`，内圆自己 resize 再设 x/y。不要把 60 的圆 `resize` 成 85。
7. **还原产品能看见的；丢掉导入垃圾。** 半截进度线、错位徽章，是稿。叠在一起穿出透明边的矢量，按可见边缘重画，不要整组 clone。
8. **用户指着原稿说「有」，就加回去。** 不要解释「我帮你整理了」。吃不准：**默认还原 + 再做一条变体**让他切。
9. **一屏对照再宣布完成。** 组件 vs 溯源并排截图。差 2px 的对齐、半截线、气泡位置，以原稿为准。
10. **一次 `use_figma` 只做一件可验证的事。** 失败=整段没执行。颜色 0–1。每调用最多一次 `setCurrentPageAsync`。禁止 `figma.notify` / `console.log`。

API 细节：[references/plugin-api-traps.md](references/plugin-api-traps.md)。

## 2. 变体 / 属性 / 变量

### 2.1 变体轴（VARIANT）

原稿里同一组件、不同样子，就做轴。默认轴名 **`状态`**（中文规范页好扫）；Size / Type / 平台 等独立维度用**第二轴**，不要揉进 `状态`。

| 类型 | 做成 |
|---|---|
| 流程位置、选中、空态/回填、禁用 | `状态` |
| 会改整段结构的装饰（下移让出气泡、加一行） | `状态`（不要只用 BOOLEAN 硬藏） |
| 互相独立的第二视觉（进度线半截 vs 整段） | 第二轴；默认 = 原稿；目录放不下就隐藏非默认变体 |

**不要发明原稿没有的态。** 四步看起来一样 → 只留默认。某一修饰只出现在徽章上 → 只做徽章变体，不要凭空做一套原子。

### 2.2 组件属性

| 用 | 不要 |
|---|---|
| TEXT：标题、序号、按钮文案 | 每个状态下写死不同数字/文案 |
| BOOLEAN：箭头/徽章显隐（不改变高度） | 显隐会改变 pad/高度时仍用 BOOLEAN |
| 暴露子实例 / INSTANCE_SWAP | 组合条里的每一项还是 Frame |

TEXT 绑在**变体主组件的图层**上，不能绑实例子层。一套 TEXT 只有一个 `defaultValue`：改「当前」主组件的数字，「未到」主组件也会变。目录预览用实例 `setProperties`；主集可隐藏。  
`isExposedInstance` 必须在实例已经进父组件之后再设。

### 2.3 Figma 变量

能对上**该产品**语义 token 的 fill / 字号 / 间距 / 圆角，就绑变量，并设 **scopes**（禁止 `ALL_SCOPES`）。  
对不上的一次性色按原稿写死，记进 spec，不要假装成 Brand、也不要另造第二套主色。

## 3. 搭建顺序

1. **原子**（点、芯片、勾）：只要视觉态。数字若随父级变，内层数字透明，父级 Absolute TEXT 绑 `序号`。
2. **项**（原子 + 标题）：嵌原子实例；切 `状态` 只换皮。
3. **条 / 面板**：AL 排项；装饰 Absolute 且先插入（z 在下）。
4. **目录卡**：对齐该文件已有规范页（本仓库选择器：Header + Section 横向组件集，`状态` 标签格宽 = 变体宽）。
5. **文档**：写右栏能切什么、不会跟着变什么、溯源 ID、两态肉眼差别。路径按该仓库约定（本仓库 `docs/specs/NN-xxx.md`）。

命名：`域/中文 EnglishName`，变体名 `状态=当前` 或 `状态=步骤2, 2到3=半段白`。

## 4. 换场景时只换输入

| 场景 | 怎么套 |
|---|---|
| 同一规范页的下一刀（图标、表单、弹层） | 同一目录骨架；新溯源；能复用的原子直接嵌，禁止再画一颗同款圆 |
| 同一设计体系、另一业务（理财、到店…） | 同一 token / 画布 / 组件库；换文案、字段、溯源；模式（空态、回填、当前步）照搬 |
| 另一 Figma 文件 / 另一产品 | 换 fileKey、画布、设计系统 skill；**本 skill 的拆法照旧** |
| 不是步骤条 | 选择器、表单行、Tab、导航、列表、滚轮…凡原稿有空/选中/禁用，就做 `状态` |

步骤：dump 每个状态一份 → 锁矩阵 → 原子→项→条 → 并排截图 → 用户指哪笔改哪笔。  
**不要假设和已做组件同构。** 两份「步骤条」也可能列宽、y、装饰坐标全不同。

## 5. 验收

- [ ] 点实例，右栏能切锁过的每一轴
- [ ] 切 `状态` 后 TEXT / 变量绑定还在
- [ ] 组合里的项是暴露实例，不是 Frame
- [ ] 组件截图 vs 溯源截图：线、尺寸、装饰坐标、字重一致
- [ ] 透明热区里没有穿出的残段
- [ ] 没有把「整理掉的原稿细节」写成规范
- [ ] 没有把理赔文案或支付宝 token 抄进无关产品

---

## 6. 禁止

- 把本 skill 理解成「只做理赔步骤条」
- 用 Frame 冒充分状态组件
- 把两份原稿收成一种更干净的设计
- 用 `resize` 放大带装饰的组
- 在实例子层绑 TEXT 属性
- 为目录好看发明原稿没有的态
- 整组 clone 导入叠线
- 没并排截过原稿就宣布完成
