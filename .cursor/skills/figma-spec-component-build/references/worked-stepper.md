# 对照例：申请步骤条（理赔场景，方法可迁移）

这是**练过的一个场景**，用来钉死「变体策略 + 原稿还原 + 别整理过头」。  
换业务时：换文件、文案、溯源 ID；拆法（原子/项/条、状态与序号分离、两份原稿不当一份）照旧。

## 矩阵（做对的拆法）

| 组件 | 轴 | 属性 | 溯源 |
|---|---|---|---|
| `步骤条/申请步骤点 AppStepDot` | `状态` 已完成 / 当前 / 未到 | 无（数字由父级画） | `367:6050` / `367:6043` / `367:6047` |
| `步骤条/申请步骤项 AppStepItem` | 同上 | TEXT `标题` `序号` | 点实例 + 标题 |
| `步骤条/申请步骤条 AppStepper` | `状态` 步骤2 / 步骤2-可修改；`2到3` 半段白 / 整段底 | 三步暴露为项实例 | `367:5998` / `367:6179` |

未到点：**60×60** 圆 `#6CA0FF` + 描边 `#1677FF` 4，居中在 **85** 槽。不是 85 的实心圆。

## 点得着

申请步骤条里点「填写就医情况」应选中 **AppStepItem 实例**（菱形）。  
若点到「点槽」Frame：切不了；切 当前/未到 还会把烤死的 2/3 一起换掉。

## 状态与序号解耦

- AppStepDot 当前/未到 内层数字 **opacity 0**
- AppStepItem 上 Absolute TEXT 绑定 `序号`，对齐 85 槽（当前）或 60 圆中心（未到）
- 实例属性：第 1 步 `序号=1`，第 2 步 `2`，第 3 步 `3`
- 切第 2 步 `状态=未到`：仍是「填写就医情况 / 2」，只是点变成 60 环

## 两份原稿的差别（不是同一条）

| | 步骤2 `367:5998` | 步骤2-可修改 `367:6179` |
|---|---|---|
| 点 y | 21 | 42 |
| 连线 y | 64 | 85 |
| 气泡 | 无 | 编组-4 Absolute **(160, 24)**：第 1 步右侧、1→2 线上方 |

气泡不要做成第 1 列里居中的胶囊，也不要改变 144 列宽。

## 连线：还原看见的，丢掉穿模的

产品看见：

1. 1→2 白 + 步骤 2 前一小段 `#6CA0FF`
2. 2→3 **半截白**（`375.5` × `129.5`）再接底色
3. 底色接到步骤 3 的 **60 圆左缘 `x=604`**

不要：

- 整组 clone 六条叠线
- 把半截白「整理」成整段底（用户会问为什么不还原）
- 让底线画进 85 槽右侧，圆两边漏残段

吃不准时：默认 **半段白**（原稿），另做 `2到3=整段底` 可切；整段底目录可隐藏。

## 目录

- 规范页组件集是全家福。切状态请点**实例**。
- AppStepItem 主组件因 TEXT 默认值共用，当前/未到主组件可能都显示「3」→ 集 `visible=false`，卡上放预览实例（1/2/3）。
- AppStepper 目录只展示两个默认态（半段白）；第二轴在实例右栏切。

## 以后不要再犯

1. 看见「乱」先并排截原稿，再决定是穿模还是半截白。
2. 用户说「2 到 3 有半截白线」→ 按坐标加回去，不要辩论。
3. 新组件先问：切了状态，数字和标题还会不会错。会错就把它们做成属性。
