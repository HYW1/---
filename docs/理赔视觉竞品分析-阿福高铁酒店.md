## 一、分析背景与目标

### 1.1 背景

理赔失败/退单，常见根因不是用户「不愿配合」，而是：

1. **不知道要交什么**（材料清单抽象、示例缺失）
2. **交了但对不上**（字段看不清、凭证截不全、关键信息被弱化）
3. **交完才发现错**（事前无校验，事后才报错）

阿福（生活服务）、定高铁（出行）、酒店（住宿）覆盖三类高频凭证形态：

| 场景 | 典型凭证 | 理赔常卡点 |
| --- | --- | --- |
| 阿福类 | 服务订单、票据、明细、门店凭证 | 票据真伪/完整性、明细是否可核对 |
| 定高铁 | 车次票面、行程、延误/改签证明 | 时间字段准确性、座位/车次可辨识度 |
| 酒店 | 入住单、发票、房型/入住人信息 | 入住真实性、取消政策与费用构成 |

### 1.2 目标

1. 识别三类场景中，**对理赔有用的视觉做法**与**拖累理赔的视觉问题**
2. 提炼可复用的「理赔友好」视觉原则
3. 输出可落地的优化建议（信息架构 / 组件 / 色板与图标）

### 1.3 分析边界

| 在范围内 | 不在范围内 |
| --- | --- |
| 订单详情、票面/凭证、政策说明、材料上传指引、状态进度 | 核保规则、理赔审核策略、客服话术 |
| 视觉层级、示例图、标注、容错反馈 | 纯运营视觉、品牌调性审美评审 |

## 二、分析维度（理赔视角）

> 每个维度都要能落到「截图 + 一句判断」。空泛形容词（高级、清爽）一律不用。

| 维度 | 理赔关注点 | 评估看什么 | 评分（建议） |
| --- | --- | --- | --- |
| A. 信息清晰度 | 关键字段能否 3 秒定位 | 字号层级、对比度、分组、必填/选填区分 | 1–5 |
| B. 证据导向性 | 是否教会用户「拍什么、怎么拍」 | 示例图、标注框、正反面/角度指引、合格/不合格对比 | 1–5 |
| C. 容错与提示 | 能否事前防错、即时纠错 | 校验时机、错误文案位置、视觉反馈强度 | 1–5 |
| D. 流程可视化 | 是否降低焦虑、减少放弃 | 步骤条、状态机、预计耗时、材料完成度 | 1–5 |
| E. 多模态呈现 | 是否降低理解成本 | 图文对应、图标表意、关键数字可复制/放大 | 1–5 |

**加分项（场景专属）：**

- 阿福：票据四角完整、印章/金额可读、明细可放大
- 定高铁：发到站时间权重、车次号可读、延误证明入口可见
- 酒店：入住人/房型/入住离店日期并置、发票信息预填提示

3. **缺交易凭证**：几乎没有订单金额/发票页，理赔仍需跳到支付或医院凭证。

## 六、跨场景共性洞察

> 截图补齐后，用事实改写本节；以下为「理赔视觉」常见规律，作初稿。

### 6.1 优秀实践

| 实践 | 表现 | 对理赔的作用 |
| --- | --- | --- |
| 证据有效性前置 | 上传前展示合格/不合格对比 | 降低退单与补件 |
| 关键字段强化 | 时间/金额/身份用字号+色+位置三件套 | 3 秒可核对 |
| 证据组打包 | 「订单截图 + 支付凭证」成套展示 | 减少用户自行拼材料 |
| 流程可见 | 材料完成度 2/5、下一步要做什么 | 降低放弃率 |
| 事前校验 | 模糊/缺角即时拦截，而非提交后驳回 | 缩短周期 |

### 6.2 共性问题

| 问题 | 表现 | 后果 |
| --- | --- | --- |
| 场景化示例缺失 | 一张通用「上传照片」插图打天下 | 细分场景材料不合格 |
| 事后报错 > 事前引导 | 提交后才说缺字段 | 情绪差 + 重复提交 |
| 政策视觉弱 | 取消/延误规则灰字长文 | 争议与客诉 |
| 多端不一致 | App / 小程序 / H5 字段层级不同 | 用户学习成本上升 |
| 理赔入口隐蔽 | 「保险」藏在更多里 | 用户找不到证明获取路径 |

### 6.3 三类场景差异（设计时不要一套稿打天下）

| | 阿福类 | 定高铁 | 酒店 |
| --- | --- | --- | --- |
| 证据核心 | 票据完整性与明细可读 | 时间与车次准确性 | 入住真实性与人证一致 |
| 视觉重点 | 示例标注、放大、四角检测提示 | 时间对比、证明入口 | 入住人/日期并置、政策结构化 |
| 高风险交互 | 拍照裁切 | 折叠掉关键时刻 | 取消政策折叠过深 |

## 七、理赔视觉体验优化建议

### 7.1 信息架构层

1. **理赔字段优先级规范**
   - L1 必填（时间/金额/身份/凭证主体）→ 最大字号 + 高对比 + 置顶分组  
   - L2 选填 → 次级字号，可折叠  
   - L3 参考说明 → 弱化，不进首屏关键区
2. **证据组（Evidence Group）**
   - 按「证明一件事」打包：如「出行发生」= 票面 + 行程状态；「费用发生」= 支付明细 + 发票  
   - 组内展示完成态勾选，组外展示总进度

### 7.2 交互与容错层（原稿缺 5.2，此处补回）

1. **上传前**：合格/不合格对比 + 拍摄框线（四角、倾斜、反光检测的视觉提示）  
2. **上传中**：清晰度/完整度即时反馈（成功绿 / 重拍橙）  
3. **提交前**：材料齐全度检查清单，缺项不可点亮主按钮  
4. **提交后**：补件只高亮缺失项，不整单打回式文案

### 7.3 视觉表现层

1. **理赔友好色板**：正文高对比；状态色仅用于「成功/警告/失败」，不用品牌色表达状态  
2. **理赔图标系统**：材料类型图标固定语义（票面/发票/身份证/延误证明），禁止同图标多义  
3. **进度情感化**：用完成度与下一步文案缓解焦虑；动效只服务状态变化，不装饰

### 7.4 分场景专属优化

| 场景 | 视觉重点 | 专属动作 |
| --- | --- | --- |
| 阿福类 | 票据规范性 | 真伪/完整提示；明细可放大；字段级标注示例 |
| 定高铁 | 时间准确性 | 发到站时间一级权重；计划 vs 实际对比条；延误证明入口前置 |
| 酒店类 | 入住真实性 | 房卡/入住凭证示意 + 入住人双校验提示；取消政策结构化色条 |

### 7.5 建议落地顺序

1. 先统一 **P1 订单详情** 的 L1 字段规范（三类场景各一版）  
2. 再补 **P5 上传示例** 的合格/不合格组件  
3. 最后做政策页结构化与多端一致性走查
